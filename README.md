# 记忆压缩焕新（astrbot_plugin_fish_memory_core）

让 **群聊和私聊共用同一份长期记忆** 的 AstrBot 插件。

普通的机器人：私聊一套上下文、群聊一套上下文，互不相通；聊得越久越贵、越乱，最后只能一刀清空，什么也不剩。

这个插件换了个思路——**不靠上下文记住你，靠一份写在磁盘上的记忆记住你。**

---

## 一、三个它能帮你解决的问题

### 1. 省 token：越聊越便宜，而不是越聊越贵

上下文是每次请求都重发一遍的。聊到第 200 轮，上下文堆到 8 万字，你每说一句"在吗"，都要先为这 8 万字付一次输入费。

本插件的做法是：**每天定时把这堆上下文压成 1~5 千字的记忆文件，然后清空上下文。**

```
不清：第 200 轮 → 输入 8 万字 → 便宜不了
清了 + 记忆：第 200 轮 → 输入 5 千字 → 只剩零头
```

- 上下文常年停在很小的水位，不再滚雪球。
- 记忆文件有 `inject_max_chars` 刹车，超过上限只注入最新的部分，不会失控。
- 压缩和审核优先走**本地模型**（LM Studio / 任意 OpenAI 兼容端点），本地免费，只有审核才叫主模型，费用可控。

### 2. 长期记忆：记得住关系，不只是记得事实

大多数"上下文压缩"插件留下的是"用户询问了 X，助手回复了 Y"这种流水账。这种摘要第二天接不上话。

本插件的压缩提示词强制模型写清五件事：

1. 我对主人的看法
2. 我对自己的看法
3. 我的心理与情绪
4. 我们之间做了什么（具体事件，不是概括）
5. 印象最深刻的事（要有细节）

写完还有**质量审核**：由主模型（默认）或本地模型当审核员，检查这五项有没有缺、有没有编造；不合格就丢回去重写，**最多重写 5 轮**才收。

所以第二天醒来，接的是"上次你还在改机器，凌晨三点说什么都不肯睡"，而不是"上次我们讨论了机器人相关话题"。

而且记忆是**一份持续追加的文件**，不是按天过期的日志——聊一个月、聊一年，它一直在同一个文件里往后长。

### 3. 简单易用：两条命令，一次绑定

不需要配置数据库、不需要理解会话 ID、不需要写脚本。

```
私聊里发：/记忆绑定
群里发：  /记忆绑定
```

就完了。之后这两条会话读的是同一份记忆、写的是同一个文件、每晚一起压、一起清。

- 记忆文件放**公共目录**（`data/plugin_data/fish_memory/`），私聊和群的目录隔离对它不起作用。
- 定时触发不依赖"上下文涨到 80%"，**每天固定时间**（默认 23:40）压一次，节奏稳定。
- 内置 `dry_run` 演练模式：只压不写不清，先看摘要质量再开真的。
- 压失败**绝不清上下文**——先写文件，写成功才清。

## 二、它到底怎么工作（思路）

### 1. 只用一份文件

```
data/plugin_data/fish_memory/
├── 长期记忆.md        # 压缩后的记忆，会注入上下文
└── 聊天原文存档.md    # 每天的原文，只存档、不注入
```

AstrBot 的工作区是按会话隔离的，私聊和群是两个目录。文件放公共目录，两边才读得到同一份。

### 2. 每轮注入：所有绑定会话读同一份

插件挂 `on_llm_request`，每次请求模型前，把 `长期记忆.md` 追加到 `system_prompt` 末尾，带 `【长期记忆】` 标记防重复注入。

于是：群里聊过的、私聊聊过的，只要被压进这份文件，**两边都看得到**。

### 3. 每晚定时压缩：把上下文"搬"进记忆

默认每天 `23:40` 触发（可改）：

```
读取绑定的 N 条会话的聊天记录
        ↓
原文（含时间、来源）追加进 聊天原文存档.md
        ↓
喂给模型压缩，生成 600-1200 字"第一人称记忆"
        ↓
质量审核，不合格重写（最多 5 轮）
        ↓
摘要追加进 长期记忆.md
        ↓
N 条会话的上下文一起清空
        ↓
私聊给主人报一声
```

关键点：**先写文件，再清上下文**。写不进去就绝不清，宁可下次再来。

### 4. 本地模型优先，兜底能用

- 到点先看本地模型在不在（`http://127.0.0.1:1234/v1`）
- 不在 → 私聊提醒主人打开，最多等 `wait_minutes` 分钟
- 等不到 → 自动改用主模型（DeepSeek 等）压
- 本地模型只做压缩和重写，审核默认交给主模型（本地自评容易护短）

## 三、安装

1. 把整个目录丢进 `AstrBot/data/plugins/astrbot_plugin_fish_memory_core/`
2. 装依赖：`pip install aiohttp`（AstrBot 一般已有）
3. **彻底重启 AstrBot**（热重载不一定能绑定新插件的钩子）
4. 在 WebUI 插件配置里填 `owner_qq`
5. 在私聊里发 `/记忆绑定`，在要共用的群里发 `/记忆绑定`
6. 发 `/记忆状态` 检查：会话条数、文件大小、本地模型是否在线

### 先演练一遍（强烈建议）

配置里把 `dry_run` 设成 `true`，手动发一次 `/压记忆`。
它会把摘要打印/私聊给你看，但**不写文件、不清上下文**。满意了再关掉演练。

## 四、命令

| 命令      | 谁能用 | 作用                        |
| ------- | --- | ------------------------- |
| `/记忆绑定` | 主人  | 把当前会话加入共享记忆               |
| `/记忆解绑` | 主人  | 移出共享记忆                    |
| `/压记忆`  | 主人  | 立刻压一次（会清空上下文）             |
| `/记忆状态` | 主人  | 看绑定了哪些会话、各多少条、文件多大、上次压的时间 |

## 五、配置

| 键                             | 默认                         | 说明                                     |
| ----------------------------- | -------------------------- | -------------------------------------- |
| `enabled`                     | true                       | 总开关                                    |
| `schedule`                    | `23:40`                    | 每天几点触发                                 |
| `owner_qq`                    | 空（必填）                      | 主人 QQ，只有他能操作                           |
| `platform`                    | 空（自动）                      | 平台 ID，留空则从事件里取                         |
| `targets`                     | `[]`                       | 固定绑定列表，一般用 `/记忆绑定` 就够                  |
| `mem_dir`                     | 自动                         | 记忆目录，默认 `data/plugin_data/fish_memory` |
| `mem_file`                    | `长期记忆.md`                  | 记忆文件名                                  |
| `raw_file`                    | `聊天原文存档.md`                | 原文文件名                                  |
| `inject_only_targets`         | true                       | 只在绑定会话注入（关掉会让别人也读到）                    |
| `inject_max_chars`            | 60000                      | 每轮最多注入多少字                              |
| `digest_input_chars`          | 24000                      | 喂给压缩模型的原文上限                            |
| `clip_per_message`            | 800                        | 单条消息最多保留多少字                            |
| `max_rounds`                  | 5                          | 质量不过最多重写几轮                             |
| `review_enabled`              | true                       | 是否开质量审核                                |
| `reviewer`                    | `provider`                 | 审核员：`provider` 或 `local`               |
| `local_base`                  | `http://127.0.0.1:1234/v1` | 本地模型地址（LM Studio）                      |
| `local_model`                 | `qwen3-14b`                | 本地模型名                                  |
| `local_timeout`               | 1800                       | 本地模型超时秒数                               |
| `wait_minutes`                | 10                         | 等本地模型起来的分钟数                            |
| `persona_name` / `owner_name` | 她 / 主人                     | 写进压缩提示词的称呼                             |
| `dry_run`                     | false                      | 演练模式：只压不写不清                            |

## 六、注意事项（重要）

### 1. 清空上下文是不可逆的

清空用的是 AstrBot 内部 DB 接口 `db_helper.update_conversation(cid, content=[])`，**没有回收站**。
插件只在"摘要已经成功写进文件"之后才清，但第一次请务必：

- 开 `dry_run: true` 跑一遍 `/压记忆`，确认摘要质量
- 备份 `data/data_v4.db` 和记忆目录

### 2. 依赖 AstrBot 内部接口，升级可能失效

用到的东西：`astrbot.core.db_helper`、`astrbot.core.sp`、`db_helper.update_conversation`、`provider.text_chat`、`on_llm_request` 钩子。开发与验证版本 **AstrBot v4.29.3**。换大版本后先跑 `dry_run` 验证。

### 3. 会话 ID 用 `sel_conv_id`

插件按 umo（如 `qq:FriendMessage:123456`）查 `sp` 里的 `sel_conv_id` 定位会话。如果用户在 WebUI 里切换了会话，绑定会跟着变；找不到会话就跳过，不会乱清。

### 4. 每轮注入 = 每轮花钱

记忆文件越长，每轮请求的输入 token 越多。10k 字的记忆 ≈ 每轮多几千 token。`inject_max_chars` 是刹车，超过就只注入末尾（最新的部分）。建议定期手工瘦身长期记忆，把冗余的旧条目删掉。

### 5. 隐私

- 记忆里会有私聊内容，插件默认 `inject_only_targets: true`，**只在绑定会话注入**，别关掉，否则别人的私聊也会读到你的记忆。
- 原文会被完整写进 `聊天原文存档.md`，**别把这个目录传到公开仓库**。

### 6. 群聊里的"别人说的话"

绑定群之后，群成员说的话也会被压进记忆、注入上下文，机器人可能混淆"谁说的"。想干净一点，就别把大群绑进来。

### 7. 没有本地模型也能用

只是压缩质量取决于主模型，且每晚会多花几十次调用。`review_enabled` 关掉能省钱，但质量自负。

## 七、和"上下文记忆管家"类插件的区别

|      | 上下文压缩类插件        | 本插件               |
| ---- | --------------- | ----------------- |
| 记忆载体 | 当天日志文件（按天，自动过期） | 一份持续追加的长期记忆       |
| 压缩重点 | 事实、数字、待办        | 关系、自我认知、情绪、印象深刻的事 |
| 群私聊  | 各压各的，注入靠日志目录    | 明确"绑定多条会话共用一份"    |
| 清理时机 | 上下文涨到阈值触发       | 每天固定时间触发          |
| 质量把关 | 审核通过即可          | 五项必写 + 最多 5 轮重写   |

两者可以共存，但**别同时开注入**，会把上下文塞两遍。
